# Synthetic Review Lab: protocol and evidence APIs

Current scope: T6 integrated validation and learner recipe, building on T1 protocols, T2 pilot/review evidence, T3 explicit CLI preparation/supervised generation, T4 native human review, and T5 qualified seals with a validated fixed-partition handoff. Full controlled training and final evaluation remain subsequent tasks. Storage modules never load or download a model; only the explicit CLI prepare command can download. No classifier improvement or real FLAN-T5 feasibility is established by the tiny offline contract tests. See README: Synthetic generation CLI for the ordered commands.

## Frozen input

Use `signallab.study.freeze_protocol` as documented in the README. It requires the original development CSV and a separate, declared-reserved final cohort. Development membership, final exclusion fingerprints and policy settings are frozen before a pilot is allocated. Keep both original CSVs and their compatible code/environment separately. Hashes are not anonymisation, semantic duplicate detection or proof of prior non-inspection.

## Pilot evidence

All functions below live in `signallab.synthetic`; run in the existing locked environment. `root` is the synthetic artifact directory; `studies_root` is the protocol directory. Defaults for creation are `artifacts/synthetic` and `artifacts/studies`.

| API | Contract |
|---|---|
| `create_pilot(protocol_id, frame, model_assets, root=..., studies_root=...)` | Re-read protocol, attach exact development frame and allocate a new private pilot identity. `model_assets` maps required allowlisted asset names to SHA-256 checksums. This records declared asset identity; it does not verify files, loadability or model readiness. The CLI does those checks before creating an execution-backed pilot. |
| `generation(root, pilot_id, studies_root=...)` | Context manager holding the exclusive generation lock. Publishes an immutable generation-start marker. The yielded writer belongs to the supervisor, not the model worker. |
| `writer.start(parent_id, input_tokens)` | Persist intent before one model call. Parent must be the next frozen training parent, input must be an integer 1–128. The CLI measures the whole prompt including special tokens, without truncation. |
| `writer.skip(parent_id, input_tokens)` | Record an intact input exceeding 128 tokens, without an intent/model call. Skips are not replenished. |
| `writer.generated(parent_id, text, output_tokens, eos)` | Retain one literal output after its intent. At most 20,000 characters and 128 output tokens. Record token count/EOS, raw-text digest and automatic exclusions. An output without EOS is ineligible. |
| `writer.failed(parent_id, error_code)` | Record a sanitized failure after intent (`worker_error`, `worker_exit`, `invalid_output`, `interrupted`). A failure stops further parent writes. |
| `writer.finish(state, resources, worker_reaped=True, error_code=None)` | Publish the immutable terminal manifest after the supervisor has stopped/reaped its worker. State is `complete`, `failed`, `interrupted` or `stopped_budget`. Sanitized terminal codes distinguish model-load, worker, measurement, interruption and budget failures. The reaped-worker flag is a supervisor attestation, not independent process verification by this storage layer. |
| `read_pilot(root, pilot_id, studies_root=...)` | Revalidate protocol, selection, identity, attempt transitions, candidate checks and terminal bindings. Does not need the original CSV/model for summary reading. |

`resources` contains `elapsed_seconds`, `peak_rss_bytes`, `samples` and `method`. The supported recorded method is `macos-ps-rss-kib-v1`, with bytes already converted by the supervisor. Unavailable measurement must use `method="unavailable"`, `peak_rss_bytes=None`, `samples=0`; it remains unknown. Observed elapsed time >=1,800 seconds or sampled peak >=4 GiB fails the resource guard. The storage API accepts declarations; the CLI supplies measured observations. If a later RSS probe fails, optional observed_peak_rss_bytes/observed_samples retain prior observations while qualifying RSS fields become unavailable. A proven wall-time breach is still a failure even if RSS is unknown. Sampled RSS cannot establish an absolute peak-memory bound. Complete status requires all selected parents resolved as generated/length-skipped and resources observed within the guard.

The supervisor must retain its context through worker cleanup. It may pass `writer.lock_fd` explicitly to its owned child to keep the generation lock held until child exit. Closing the owner's descriptor does not explicitly unlock the inherited descriptor. A reopened abandoned generation permits only interrupted finalization, never more attempts or regeneration. The CLI implements worker supervision, lifetime-channel shutdown and reaping; this storage API does not run those processes. T3-backed pilots also carry an optional execution block binding preparation ID/digest and the actual CLI/worker source, dependency and Python identities. Older T2 records remain readable with execution provenance absent.

While a generation lock is held and no terminal manifest exists, readers return immutable pilot/protocol context with `generation_state="running"`, `attempts=None` and no candidate enumeration. They deliberately do not manufacture coherent counters from racing multi-file writes. Refresh after terminal publication/release for full attempts. A lock-free unfinished pilot is `incomplete`; reading never auto-finalizes it. Pending files remain preserved.

## Automatic exclusions

Literal candidate text is retained, even for blank, unchanged, incomplete or duplicate outputs. Exclusions cover:

- Blank text; canonical text matching its parent or any original development partition.
- Canonical collision with the reserved final cohort, regardless of label.
- Output without EOS, including token-capped output.
- Duplicate candidate text: the first automatically eligible unique output owns the canonical key in frozen attempt order. Human rejection/ambiguity cannot promote a later duplicate.

The shared canonical key preserves the existing case/whitespace/known-prefix rule. It does not identify semantic duplicates. Refusals, instruction drift, wrong language, factual changes, negation and sentiment preservation remain human rubric questions. Literal text must eventually render as plain text, not executable instructions or HTML.

## Human review

Only terminal pilots can be reviewed; interrupted/failed pilots remain inspectable learning evidence. The review writer reattaches the exact original development frame and validates candidates against the frozen protocol before writing. Original parent labels are read-only and derived from the protocol, never supplied by the reviewer.

`save_review(root, pilot_id, frame, candidate_id, verdict=..., reason=..., rubric_ack=True, expected_revision=..., decision_id=..., studies_root=...)` returns the committed revision number. Verdict is `accept`, `reject` or `ambiguous`, reason is nonblank and at most 2,000 characters, and rubric acknowledgement must explicitly be `True`. An Accept decision does not override automatic exclusion or qualify an entire pilot. Ambiguous is a completed review and excludes training. No training or seal is produced by saving.

Use a fresh 32-character hexadecimal request ID for each new decision and the current integer revision. Request identity binds the complete exact payload, including reason whitespace and expected revision. A lost-response retry with the identical ID/payload returns the original committed revision even after later reviews. Changed payload under that ID, stale expected revisions, or a busy review lock raises `ReviewConflict` (a `ValueError` subtype); no replacement decision is saved. The future UI must retain the unsaved draft separately and require an explicit reload/resubmission. Do not retry a changed decision automatically.

`read_reviews(root, pilot_id, studies_root=...)` returns the latest validated snapshot, or revision 0 with empty decisions/requests before any review. It reads bounded commit metadata and only the latest full snapshot. Latest decisions are reconstructed from the full committed request history and checked, rather than trusted as an independently editable map. `read_review_revision(root, pilot_id, revision, studies_root=...)` additionally verifies and returns a selected older snapshot. Older snapshot existence/type/size is checked during ordinary reads; its full bytes are verified when explicitly opened. At most 200 revisions are allowed; reaching the bound does not prune history or overwrite evidence.

## Persistence, privacy and recovery

Artifacts live under `artifacts/synthetic/<pilot-id>/` with private POSIX directories (0700) and files (0600). Unlike saved numeric baseline reports, these are **data-bearing files**: they persist generated review text and human reasons, which may contain copied facts or sensitive content. Original source rows and final-cohort labels are not separately copied or supplied to the worker. Retained generated outputs can nevertheless reproduce original or known-cohort text, including excluded collisions; exclusion is not redaction. Local source descriptions and hashes still identify data. No raw corpus export, hosted upload or automatic deletion is provided.

Publication uses exclusively created pending bytes, file fsync, atomic no-overwrite hard-link publication and directory fsync. Completed records never change. The terminal manifest binds the pilot/protocol/generation identities and every attempt digest. Reviews use numbered full snapshots plus small immutable commit metadata with a previous-digest chain. Stable locks serialize revision checking and publication. No database, background service or new dependency is required.

An fsync/publication failure never reports success. Pending files are ignored and preserved. If a review snapshot was published but its commit metadata was not, reads/writes fail as incomplete; there is no automatic promotion, deletion or repair. Preserve the files for explicit recovery rather than manually editing hashes or generating replacements until a gate passes. Missing/corrupt history, symlinks, wrong kinds/versions, oversized JSON (>16 MiB, commit metadata >4 KiB), excessive nesting and inconsistent digests are rejected. Root configuration is trusted local setup, not a hostile-user authorization boundary. Owner-wide forgery, hard OS hangs and arbitrary model execution containment are not solved by hashes or advisory locks.

## CLI execution boundary

Preparation resolves only the frozen repository/revision and allowlisted assets, checks remote size metadata before download, copies regular bytes into private immutable preparation folders, and verifies a fast tokenizer plus a standard T5 encoder-decoder using local-only safetensors loading. Missing/unexpected/mismatched weight diagnostics fail readiness rather than accepting random initialization. Config dimensions, file count and file sizes are bounded. Tokenizer/config token identities and actual CPU float32/thread settings are checked. Asset checksums and inode/size/mtime identities are checked before and after loading; a new generation checks the prepared identity again.

A new generation sends only selected training-parent text to its one worker; held-out/final raw text is never sent. The worker uses a fresh explicit greedy GenerationConfig, not saved sampling/forced-token overrides. T5 encoding disables token_type_ids, measures the entire instruction and review with special tokens, and does not truncate. The supervisor persists intent before sending Generate and retains all bounded output, including automatic exclusions. See [Transformers generation4.57](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/text_generation) for token controls and why a cooperative max_time alone is insufficient as a stop guard.

IPC uses bounded 128-KiB framed messages over a local socket pair, not stdout review logs. A separate lifetime pipe starts its watchdog before ML imports. The owned child inherits the generation-lock descriptor. Sampled macOS ps RSS is converted from KiB to bytes; the probe itself has a one-second timeout. Wall checks begin before worker launch and include loading/inference; parent cleanup only signals its own Popen child handle and reaps before terminal publication. Unknown measurement, unexpected worker exit and malformed output stop without retries. OS stalls, unsampled RSS excursions and system-wide memory are outside this sampled guard.

Cache-only generation refuses missing/changed/incompatible preparations before pilot allocation. Preparation discovery is bounded to 50 immediate entries, with explicit --prepared selection if needed; there is no implicit newest snapshot. Preparation readiness binds exact source/runtime identities, so changed code/dependencies require explicit preparation again. Read-only pilot/review inspection does not require those model files or the old runtime to remain installed, provided its evidence schema is supported. Retain original inputs, artifacts, prepared assets and matching source/environment for reproduction; hashes do not archive them.


## Streamlit review workspace (T4)

Open **Synthetic Review Lab** after Experiments in the sidebar. Choose **Refresh local studies**, a frozen protocol, then a pilot. Metadata reading works without a dataset, model cache or network. Discovery scans at most 50 immediate entries per root and reports truncation; it is not a newest-first history. Unreadable, incomplete or incompatible evidence is preserved and shown separately. The selected protocol/pilot/review chain is revalidated on each rerun; running workers expose no racing attempt counts or review form.

Attach the exact original **development** CSV in the page's Development source field. The sidebar dataset does not attach it. Uploads are bounded to 10 MiB, exact identity and frozen training membership are checked, and a mismatch removes the previous pair and decision form while retaining numeric status. Never attach the reserved final CSV. Authored demo attachment is explicit and works only for its exact protocol.

The default Pending filter includes automatic exclusions. All, Accepted, Rejected, Ambiguous and Auto-ineligible filters permit inspection and revision. Original text precedes generated text, both render literally, and sentiment is read only. Accept requires preservation of meaning, polarity/negation, facts/numbers, English and meaningful rewording. Reject clear violations; use Ambiguous for uncertainty. Choose a verdict, enter a reason (up to 2,000 characters), acknowledge the rubric, and explicitly choose **Save decision and next pending**. Acceptance cannot override automatic exclusions. No automatic save or model judgment substitutes for your review.

A confirmed save shows its committed revision and advances to the next pending candidate. Another review changing the revision causes a conflict: the same pair remains visible, your unsaved proposal is retained separately, and **Reload current decision** loads the saved verdict without applying your draft automatically. Its reason remains available to copy for that candidate. While another process temporarily holds the review lock, the page may show its last verified snapshot, explicitly labeled read only, and retain the form with saving disabled until refresh. This cached snapshot never authorizes a write. After an unconfirmed disk acknowledgement, retry the unchanged proposal with its same request identity or reload; a successful retry cannot double-commit. Partial publication still fails closed. Switching candidate, source, pilot or page discards unsaved edits; navigation away requires source reattachment on return. There are at most 200 committed revisions per pilot.

Generation, review completion, resource evidence, feasibility and seal availability are labeled separately. Feasibility and seal currency come from validated storage evidence. Qualified pilots can be sealed with an exact source; the validated bundle is a read-only handoff, with no classifier improvement claim. Zero accepted candidates is a valid negative result, not a reason to replenish parents. Local pilot files persist generated text and human reasons, including excluded outputs that reproduce source text.


## Qualified seals and fixed-partition handoff (T5)

`read_handoff(root, pilot_id, studies_root=...)` returns one coherent text-free qualification/currency summary. Terminal history and seals are validated under a shared review lock; active generation exposes no racing attempt counters. Gates require complete generation, resource status pass, T3 execution provenance, all generated candidates reviewed including automatic exclusions, at least 30 accepted eligible outputs and at least 10 per class. Rejected/ambiguous candidates count as reviewed but never as trainable. The summary names unmet gates; low yield is valid evidence. Execution metadata captures preparation/model/source identities, not a new model load or proof against an owner forging local artifacts. Actual semantic quality still depends on honest human review.

`seal_pilot(root, pilot_id, frame, expected_revision=..., seal_id=..., studies_root=...)` revalidates the protocol, exact development frame, generation, automatic exclusions and committed review chain under the same exclusive lock used by review publication. The expected revision is mandatory. It publishes `seal-<seal-id>.json` with schema/kind, exact protocol/pilot/terminal/review digests, accepted candidate/parent IDs, immutable inherited labels, candidate digests and gate counts. Seals contain no raw text or reasons. A lost directory-sync acknowledgement can retry the same ID and unchanged current binding; an ID already bound to a different revision fails, never overwrites. Publication failure preserves pending evidence. No training runs.

At most 200 seals are allowed per pilot; bounded enumeration rejects more than 2,048 directory entries or malformed published seal names. Seal readers use the existing no-follow regular-file, 16 MiB JSON, depth/type/duplicate-key bounds. Invalid or incompatible evidence is preserved, never silently migrated, pruned or repaired. Current seal summaries validate committed metadata and bounded seal documents rather than loading all historical raw review snapshots. Explicit `read_seal(root, pilot_id, seal_id, studies_root=...)` also validates its selected historical snapshot and returns a `current` flag.

Any later committed review revision makes previous seals historical, even if an edit only changes a reason or restores the same accepted set. History remains readable; resealing requires the current qualified revision and a new identity. The page shows currency separately, warns before review edits, and requires explicit **Reload seal context** if the review revision changed after the seal controls appeared. Unconfirmed publication retains its request ID for an unchanged retry. Busy/mixed snapshots cannot enable sealing; cached UI evidence never authorizes a write.

`build_training_bundle(root, pilot_id, seal_id, original_frame, studies_root=...)` accepts authoritative IDs and the original development DataFrame, not caller-supplied cached protocol/seal objects. It re-reads current evidence under a shared review lock, rejects historical seals/source mismatch/tampering, reconstructs original ordered partitions without calling a splitter, and returns `TrainingBundle`:

| Field | Meaning |
|---|---|
| `splits.train`, `splits.validation`, `splits.test` | Independent original development frames, exact recorded order/text/labels. |
| `training` | A separate copy of original training rows followed by exactly the accepted automatically eligible descendants in frozen attempt order. |
| `lineage` | One row per training row: training_index, source_kind (original/synthetic), parent_id, candidate_id (null for originals). |
| `protocol_id`, `pilot_id`, `seal_id`, `review_revision`, `seal_digest` | Exact current evidence identity. |

Returned DataFrames are intentionally mutable independent copies; changing them does not mutate artifacts or other bundle frames. Never re-split `training`, and never feed it to the old raw-CSV baseline/transformer entry points. The supported example in README fits `train_baseline(bundle.training)` and evaluates only a recorded partition; it does not claim to implement controlled four-condition experiments. Reserved final text/labels are not accepted by this API. Known final-text collisions retained among generated outputs are excluded before the accepted set, even when a human marked them Accept.

CLI `seal` writes qualified evidence, while `inspect-bundle --pilot ID --seal ID --csv original.csv [--json]` exercises the actual current consumer and prints only identities, partition/train/class counts and `no_training_has_run`. It neither exports raw/augmented CSV nor fits a model. `inspect` now also reports unmet gates and current/historical seal identities. Keep the exact source CSV and compatible environment/code; digests are integrity identifiers, not anonymisation or archive copies.
